## 1. 产品概述

### 1.1 产品目标

用户提前开启屏幕录制缓存。当需要保留刚刚发生的内容时，点击保存按钮，将**最近约 30 秒**的屏幕画面保存为视频文件。

**核心约束：应用只能保存开启缓存之后的画面，无法恢复开启之前的内容。**

### 1.2 产品定位

- **类型**：本地屏幕回放录制工具
- **平台**：Android 10 及以上（待实机确认）
- **网络**：首版完全离线，不上传任何录屏内容
- **账号**：无需登录

### 1.3 典型使用场景

| 场景 | 说明 |
| --- | --- |
| 游戏精彩操作 | 游戏中出现高光时刻，事后一键保存最近 30 秒 |
| 异常复现 | 应用崩溃或异常前，保存用户操作过程以便排查 |
| 临时留存 | 保存刚刚在屏幕上看到的内容，无需全程录屏 |

## 2. 首版范围

### 2.1 包含功能

| 功能 | 说明 |
| --- | --- |
| 开始缓存 | 用户授权后，持续缓存屏幕画面 |
| 循环覆盖 | 自动丢弃超出缓存窗口的旧画面 |
| 保存回放 | 保存点击按钮之前约 30 秒的画面 |
| 悬浮按钮 | 在其他应用上方提供保存入口 |
| 通知栏操作 | 提供保存和停止入口 |
| 本地导出 | 将视频保存到系统媒体库 |
| 停止缓存 | 停止录屏，并清除未保存的缓存 |

### 2.2 首版默认参数

| 参数 | 默认值 |
| --- | --- |
| 缓存窗口 | 30 秒 |
| 录制内容 | 画面和允许捕获的应用播放声音；不录麦克风 |
| 视频编码 | H.264 |
| 容器格式 | MP4 |
| 默认清晰度 | 手机屏幕原始分辨率，保持画面比例 |
| 默认帧率 | 目标 30 fps |
| 保存路径 | `Movies/Replay30` |

### 2.3 明确不包含（首版）

- 云端存储与同步
- 视频编辑（裁剪、拼接、滤镜等）
- 账号登录与用户体系
- 开机自动录制
- 麦克风声音录制
- 自定义缓存时长（15 / 60 秒等）

> 应用播放声音使用 Android 的播放音频捕获功能。默认使用「30 秒、屏幕原始分辨率、本地保存」。

## 3. 用户与场景

### 3.1 目标用户

需要在 Android 设备上**随时保存刚刚发生的屏幕内容**的普通用户，无需专业录屏知识。

### 3.2 用户故事

| ID | 作为用户，我希望… | 以便… |
| --- | --- | --- |
| US-01 | 提前开启屏幕缓存 | 不错过任何精彩或异常瞬间 |
| US-02 | 在其他应用上方点击悬浮按钮保存 | 无需切回本应用即可保存回放 |
| US-03 | 从通知栏快速保存或停止 | 减少操作步骤 |
| US-04 | 视频自动保存到相册/媒体库 | 方便在其他应用中查看和分享 |
| US-05 | 停止缓存后释放资源 | 减少耗电和内存占用 |
| US-06 | 了解当前可保存的秒数 | 判断保存时机是否合适 |

## 4. 使用流程

```
打开应用 → 点击「开始缓存」→ 授予系统权限 → 确认屏幕录制授权
    → 开始缓存（显示运行状态）→ 切换到目标应用
    → 点击「保存回放」（悬浮按钮 / 通知栏 / 主页面）
    → 显示保存结果 → 继续使用或点击「停止缓存」释放资源
```

### 4.1 流程说明

1. 用户打开应用。
2. 用户点击「开始缓存」。
3. 应用请求必要的系统权限（通知、悬浮窗等，按 Android 版本处理）。
4. 用户确认屏幕录制授权（MediaProjection 系统对话框）。
5. 应用开始缓存，并显示运行状态。
6. 用户切换到需要录制的应用或场景。
7. 用户点击悬浮按钮、通知栏或主页面中的「保存回放」。
8. 应用保存视频，并显示实际时长与保存位置。
9. 用户点击「停止缓存」后，应用释放录屏资源。

### 4.2 授权规则

- 每次重新开启录屏时，**必须**按系统要求重新请求 MediaProjection 授权。
- **不得**绕过、伪造或持久化系统录屏授权。
- 用户须在系统授权页选择「整个屏幕」，以支持跨应用录制。

## 5. 功能需求

### 5.1 开始缓存（FR-01）

| 编号 | 需求描述 |
| --- | --- |
| FR-01-01 | 缓存须由用户主动启动，不得自动开始 |
| FR-01-02 | 未获得录屏授权时，不得开始录制 |
| FR-01-03 | 启动成功后，状态显示「正在缓存」 |
| FR-01-04 | 显示当前可保存时长，最高显示 30 秒 |
| FR-01-05 | 重复点击「开始缓存」，不得创建多个录制任务 |
| FR-01-06 | 启动过程中显示「正在启动」，并禁用重复操作 |

### 5.2 循环缓存（FR-02）

| 编号 | 需求描述 |
| --- | --- |
| FR-02-01 | 默认缓存窗口为 30 秒 |
| FR-02-02 | 缓存内容为压缩后的 H.264 视频数据（非原始帧） |
| FR-02-03 | 缓存占用不得随录制时间持续增长，须维持在上限内 |
| FR-02-04 | 缓存数据上限：视频数据不超过 **32 MB**（建议值，可实机调优） |
| FR-02-05 | 缓存不足 30 秒时，允许保存已有内容 |
| FR-02-06 | 停止缓存或进程结束后，不保证保留未保存的缓存 |
| FR-02-07 | 循环覆盖时保留 30 秒边界前的最近关键帧，避免导出花屏 |

### 5.3 保存回放（FR-03）

| 编号 | 需求描述 |
| --- | --- |
| FR-03-01 | 保存范围以用户点击保存的时刻为终点 |
| FR-03-02 | 保存过程**不得**主动停止当前录屏缓存 |
| FR-03-03 | 输出格式：MP4 容器 + H.264 编码 |
| FR-03-04 | 视频从可解码的关键帧（I 帧）开始，避免开头花屏 |
| FR-03-05 | 缓存充足时，目标视频时长为 30 秒，允许约 ±1 秒偏差 |
| FR-03-06 | 保存成功后，显示实际时长和保存位置 |
| FR-03-07 | 保存失败时，显示失败原因，并允许再次尝试 |
| FR-03-08 | 保存进行中，暂时禁用重复保存，避免重复文件和内存峰值 |
| FR-03-09 | 没有可用画面时，不生成空视频，提示稍后重试 |

### 5.4 悬浮按钮（FR-04）

| 编号 | 需求描述 |
| --- | --- |
| FR-04-01 | 获得悬浮窗权限后，在缓存运行期间显示悬浮按钮 |
| FR-04-02 | 单击按钮触发保存回放 |
| FR-04-03 | 支持拖动位置；按钮不得完全移出屏幕可视区域 |
| FR-04-04 | 区分「正在缓存」与「正在保存」两种视觉状态 |
| FR-04-05 | 拖动操作不得误触发保存 |
| FR-04-06 | 未获得悬浮窗权限时，用户仍可通过主页面或通知栏操作 |

### 5.5 通知栏操作（FR-05）

录屏期间须使用系统要求的前台服务（Foreground Service）通知。通知须提供：

| 元素 | 说明 |
| --- | --- |
| 缓存状态 | 当前是否在缓存、可保存秒数等 |
| 保存回放 | 快捷操作按钮 |
| 停止缓存 | 快捷操作按钮 |
| 返回应用 | 点击通知主体返回主页面 |

Android 13（API 33）及以上，启动前须请求 `POST_NOTIFICATIONS` 权限。

### 5.6 视频存储（FR-06）

| 编号 | 需求描述 |
| --- | --- |
| FR-06-01 | 默认保存到系统媒体库 `Movies/Replay30` |
| FR-06-02 | 文件名包含保存日期和时间，避免重名（如 `Replay_20260919_105630.mp4`） |
| FR-06-03 | 保存完成前，不向相册/媒体库暴露不完整文件 |
| FR-06-04 | 保存失败后，清理本次产生的不完整临时文件 |
| FR-06-05 | 已保存视频不随缓存停止而删除 |
| FR-06-06 | 不自动删除用户已保存的视频 |

### 5.7 停止缓存（FR-07）

以下情况应停止录屏并释放资源：

- 用户点击「停止缓存」
- 系统撤销录屏会话（MediaProjection 回调停止）
- 录屏发生不可恢复的错误

停止后须：

- 移除悬浮按钮
- 更新主页面状态为「未开始」
- 清理未保存的缓存数据
- 已在进行中的有效导出应尽可能完成保存

## 7. 权限与隐私

### 7.1 所需权限

| 权限 | 用途 | 首版 |
| --- | --- | --- |
| MediaProjection（系统授权） | 屏幕录制 | 必需 |
| `FOREGROUND_SERVICE` | 前台服务 | 必需 |
| `FOREGROUND_SERVICE_MEDIA_PROJECTION` | 录屏类型前台服务 | 必需 |
| `SYSTEM_ALERT_WINDOW` | 悬浮保存按钮 | 可选（无则降级为页面+通知栏） |
| `POST_NOTIFICATIONS` | 通知栏操作（API 33+） | 必需 |

### 7.2 明确不申请

- 摄像头（`CAMERA`）
- 麦克风（`RECORD_AUDIO`）
- 网络访问（首版无联网需求）
- 存储读写（使用 MediaStore / SAF，按 Android 版本适配）

### 7.3 隐私原则

- 只申请当前功能需要的权限，并说明用途
- 不绕过受保护内容（DRM、银行 App 等）的录制限制
- 用户停止缓存后，立即停止采集屏幕画面
- 录屏内容仅存于本地，不上传、不分析、不共享

## 8. 兼容性与性能

以下为初始设计目标，**须实机验证**后写入测试记录。

| 项目 | 目标 |
| --- | --- |
| 最低系统版本 | Android 10（API 29），待目标机型确认 |
| 目标 SDK | Android 14/15 兼容 |
| 默认清晰度 | 手机屏幕原始分辨率，保持原始宽高比 |
| 默认帧率 | 目标 30 fps，实际由设备性能与画面内容决定 |
| 编码方式 | 优先硬件 H.264 编码（MediaCodec） |
| 缓存占用上限 | 视频数据 ≤ 32 MB |
| 连续运行 | 连续缓存 30 分钟，无崩溃、无持续内存增长 |
| 保存速度 | 测试设备上，30 秒视频通常在 5 秒内完成导出 |

### 8.1 屏幕旋转

- 首版使用**启动时确定的输出画布**（固定分辨率）
- 旋转屏幕后保持内容比例，允许出现黑边
- 设备无法正确处理旋转导致画面异常时，提示用户停止后重新开始

### 8.2 功耗与发热

- 长时间录屏会增加耗电和发热，属正常现象
- 应用**不得**承诺零耗电或在所有设备上维持固定帧率

### 8.3 锁屏行为

- 锁屏后按系统默认行为处理
- **不承诺**锁屏后继续录制；部分设备可能在锁屏时结束 MediaProjection 会话

## 9. 异常处理

| 异常情况 | 预期行为 |
| --- | --- |
| 用户取消录屏授权 | 返回「未开始」状态，提示「已取消授权。尚未开始缓存。」 |
| 悬浮窗权限被拒绝 | 保留主页面和通知栏操作入口，不崩溃 |
| 缓存不足 30 秒 | 保存已有片段，显示实际时长 |
| 没有可用画面 | 不生成空视频，提示稍后重试 |
| 存储空间不足 | 提示保存失败，清理不完整文件 |
| 系统结束录屏会话 | 停止缓存，释放资源，更新 UI |
| 手机锁屏 | 按系统行为处理，不承诺继续录制 |
| 受保护页面无法录制 | 接受系统黑屏输出，不尝试绕过 |
| 编码器初始化失败 | 提示失败原因，允许用户重新开始 |
| 应用被系统终止 | 未保存缓存可能丢失；已保存视频保留 |
| 保存过程中再次点击保存 | 忽略或禁用，避免重复导出 |

## 10. 验收标准

测试方法：使用带有**秒表**和**变化画面**的屏幕进行验证。

| ID | 验收项 | 通过标准 |
| --- | --- | --- |
| AC-01 | 回放时间正确 | 连续缓存 ≥ 40 秒后保存，视频覆盖点击前约 30 秒，允许 ±1 秒偏差 |
| AC-02 | 短缓存可保存 | 开启约 10 秒后保存，获得约 10 秒视频，不含开启前内容 |
| AC-03 | 保存不中断缓存 | 保存完成后继续操作并再次保存，第二段视频包含后续新画面 |
| AC-04 | 视频可播放 | 系统播放器可正常打开；开头无明显花屏；时间顺序正确 |
| AC-05 | 操作入口有效 | 主页面、悬浮按钮、通知栏均可触发保存；拖动悬浮按钮不误触 |
| AC-06 | 停止有效 | 停止后不再采集画面；悬浮按钮移除；缓存资源释放 |
| AC-07 | 错误可恢复 | 拒绝权限、取消授权、保存失败时应用不崩溃 |
| AC-08 | 资源使用稳定 | 连续运行 30 分钟，缓存占用保持在设定上限内 |
| AC-09 | 文件保持完整 | 相册仅显示完成保存的视频；失败导出不遗留损坏文件 |

## 13. 术语表

| 术语 | 定义 |
| --- | --- |
| 缓存 | 应用在内存/缓冲区中持续保存的最近屏幕录制数据 |
| 缓存窗口 | 循环缓冲区保留的最大时间范围，默认 30 秒 |
| 保存回放 | 将缓存中指定时间范围内的画面导出为 MP4 文件 |
| MediaProjection | Android 系统提供的屏幕捕获授权机制 |
| 关键帧（I 帧） | H.264 编码中可独立解码的完整帧，导出须从此类帧开始 |
| 前台服务 | Android 要求在后台持续录屏时必须展示的通知与服务类型 |
| 受保护内容 | 系统禁止录制的 DRM 或安全页面，通常显示为黑屏 |

## 14. 技术约束附录

> 本节供开发与测试参考，描述首版实现方向，不作为用户可见功能承诺。

### 14.1 架构概要

```
MainActivity（UI + 授权）
    ↓ Intent
ReplayService（前台服务：录屏、缓存、导出、通知、悬浮窗）
    ↓
ReplayBuffer（30 秒循环 H.264 帧缓冲，上限 32 MB）
    ↓
MediaCodec（H.264 硬件编码）+ MediaProjection（屏幕捕获）
    ↓
MediaStore（导出至 Movies/Replay30）
```

### 14.2 缓存数据结构

- 缓冲单元为编码后的 H.264 帧（含 PTS 时间戳与关键帧标记）
- 窗口大小：`30_000_000` 微秒（30 秒）
- 字节上限：`32 MB`
- 超出窗口时，保留边界前最近关键帧并丢弃更早数据
- 导出时对缓冲做快照（snapshot），不中断写入

### 14.3 关键实现约束

| 约束 | 说明 |
| --- | --- |
| 单录制任务 | 全局仅一个 ReplayService 录屏实例 |
| 保存与缓存并行 | 导出使用 buffer 快照，保存期间缓存继续运行 |
| 授权不可持久化 | 每次「开始缓存」重新走 MediaProjection 授权流程 |
| 文件原子性 | 先写临时文件，完成后通过 MediaStore 入库并通知扫描 |
| minSdk | 29（Android 10） |
